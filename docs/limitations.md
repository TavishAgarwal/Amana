# AMANA: Assumptions, dependencies, limitations

## What was built (verified by tests in this repo)
Lab issuer, national token service, synthetic population (calibrated to 4.8%), private check with OpenMined PSI 2.0.6 (count-only and intersection mode), in-process and Node relays, attack demo, consent ledger with hash-chained audit (memory and Postgres), case routing and sign-off rules, mock adapters, explainer with fact-checker, 15 cards, 100-prompt red-team set, evaluation harness, country-pack config swap.

## Apps (built, browser-tested on desktop only)
`apps/wallet` (Arabic right-to-left and English, light/dark, installable manifest, QR pairing code, my result, card + teach-back, check, two-step reveal, sharing/revoke/audit, withdraw-all) and `apps/console` (tier queue, case + sign-off, dashboard, attack demo), backed by `services/demo-api` and `services/relay`.

**Since 9 Nov the private check runs between the two devices** (`apps/wallet/lib/check.ts`): each phone gets its lab-signed result and national tokens once, bound to its own device key (Ed25519, non-extractable), and keeps them encrypted in IndexedDB. The check runs in the browser with `psi.js` 2.0.6 over the relay; the QR carries the relay session. The demo API no longer holds wallets or serves anyone's genes; every consent, revoke and log read is signed by the device key. Verified by: two wallets over the real relay (`apps/wallet/tests/check.test.mjs`), Python–browser signing interop (`sign-interop.test.mjs`), `services/demo-api/tests`, and a full run in two browser tabs with separate storage (`localhost` and `127.0.0.1`): sign-in, verified result, pair by code, both sides "shared", reveal only after both agreed (HBB only), share, revoke, counsellor blocked (403). The server log showed no check traffic.

## NOT built or NOT done
- **Tested in the iOS Simulator only** (iPhone 17, iOS Safari and as a home-screen web app: Arabic RTL, English, dark mode, full flow incl. sharing/revoke) — not on real phones. Home-screen install works (manifest + icons, standalone, safe-area padding), and a service worker caches only the app shell and shows a bilingual offline page when there is no connection (verified on iOS with the server stopped; /api and health data are never cached) — the app still needs the demo API for sign-in and consents (the check itself runs between the devices); camera QR scan is built (jsQR; decoding verified with a round-trip test, but a live camera was not tested because the simulator has none; it falls back to the shown code); optional PIN app lock with the cached result encrypted on the device (AES-GCM, PBKDF2 310k iterations, tested), while the result itself now lives in the device's encrypted IndexedDB store; automated axe-core WCAG 2.1 AA scan found 0 violations on 6 wallet pages (ar + en), but no manual screen-reader (VoiceOver/TalkBack) test, Arabic strings are drafts, no read-aloud, booking screen, or family invites.
- **No automated browser end-to-end tests of the full flow** (the wallet has unit tests for the vault and QR decoding; the flow itself was checked by hand in the simulator).
- **Two real phones not yet tested.** Phones reaching a laptop over plain `http://<ip>` are not a secure context, so WebCrypto and the camera are blocked; this needs HTTPS for the wallet and `wss://` for the relay (comes with deployment). Tested so far: two browser tabs with separate storage on one laptop.
- **Azure:** nothing deployed (student credit conserved); no Key Vault; no Azure OpenAI, so no AI rewording.
- **Human work not done:** clinical advisors, native-speaker review of Arabic, user test (n>=20), two-reviewer red-team review, video, deck.
- Load test (`docs/evaluation-report.md`): single-core Python run, 100,000 extrapolated; k6 relay scenario written but not run; no AED cost.
- **Panel size:** the real Abu Dhabi programme screens 570 genes; the prototype panel has **111**. The official 570-gene list was not available, so how far the two overlap is unknown. Say "111 genes" for anything the prototype does.
- Gene panel is now real (111 autosomal-recessive genes with ≥5 ClinVar pathogenic/likely-pathogenic alleles; inheritance is a hand-curated list, not read from ClinVar, and needs clinical review). Frequencies: relative gene frequencies now come from gnomAD v4 (Middle Eastern group) x ClinVar pathogenic/likely-pathogenic variants (`packs/abu-dhabi/frequencies.csv`), scaled so couples hit the 4.8% target; couples are still simulated. These are **under-estimates**: they count only variants present in both ClinVar and gnomAD, the Middle Eastern group is small (about 2,900 people) so rare genes are noisy (10 genes have none and fall back to pooled frequency), gnomAD under-represents Arab and consanguineous populations, and variants above 2% pooled frequency are dropped as artefacts or low-penetrance alleles. **CTGA is not used**: it is a catalogue of variants reported in Arab populations, not carrier frequencies, and no download terms were found; real Arab-population frequencies need a data-sharing agreement with the Center for Arab Genomic Studies or a national genome programme; cards are `pending clinical review`; understanding and fairness metrics unavailable.
- Honest-but-curious assumption; patent check and Emirati Genome Programme status not verified.
- Deviations: Python packages named `token_service` etc. instead of `app/`; own tiny i18n and plain CSS instead of next-intl/Tailwind; demo-api added.
